  1. 1

    Identity rail, 4px. The author's role colour. It is the only full-height element, so a scan down the thread reads as a colour sequence before any text is parsed.

  2. 2

    Restriction hatch, 12px. Present only on internal entries, in warm neutral. A texture, never a hue, so it cannot be mistaken for a fourth role.

  3. 3

    Avatar and role chip. Same hue family as the rail, at tag strength. The chip names the role, never a generic label like "SGS user".

  4. 4

    Visibility chip. Always slate, always present, dashed border and lock when internal, solid border and eye when shared. Audience is never inferred from silence.

  5. 5

    Surface. White for shared, warm #F9F7F3 for internal. The tint is deliberately weak — the hatch does the work, so the tint survives printing and colour-blind vision.

Rules that hold everywhere

One thread per Service Request, Review and Workspace — the component is the same, only the parent id changes.

Visibility is decided by the selector, not the renderer: a Customer session is never sent an internal row, so no styling mistake can leak one.

The Audit Trail stays a separate, immutable record. The thread shows status events for context; it is not the legal history.
